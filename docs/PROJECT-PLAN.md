# MoonRdiff 项目计划书与开发安排

编制日期：2026 年 11 月 10 日  
项目名称：MoonRdiff（暂定）  
项目定位：纯 MoonBit 远程差量计算与补丁还原库  
计划周期：2026 年 11 月 10 日至 11 月 30 日  
当前状态：方案阶段，尚未实现或完成兼容性验证。以下日期为内部开发目标，不代表官方比赛截止日期。

## 一、项目概述

MoonRdiff 面向备份、文件同步和资源更新工具的开发者，提供可嵌入应用的文件摘要生成、差量计算和补丁还原能力。

当接收端已有旧文件、发送端持有新文件时，接收端先生成并提供旧文件的分块摘要。发送端仅使用摘要和新文件计算差量，接收端再利用旧文件和差量重建新版。项目旨在减少重复数据传输，并让 MoonBit 应用能够直接使用这一能力。

核心交付物为 Mooncakes 软件包，同时提供命令行工具、跨实现兼容测试和两个可运行示例。算法和格式处理由 MoonBit 实现，辅助脚本承担测试编排与结果整理。

## 二、社区价值与项目边界

### 2.1 预期贡献

1. 为 MoonBit 开发者提供可复用的远程差量基础库，支持备份、同步和离线资源更新等应用。
2. 通过明确的兼容格式与公开测试，降低与现有工具交换数据的成本。
3. 提供跨后端实现、文档和独立消费者示例，方便其他项目接入。
4. 公开性能与失败案例，帮助使用者判断何时差量更新值得采用。

贡献效果以可安装、可互通、可集成衡量。外部采用属于后续目标，示例程序与测试不能冒充真实用户采用。

### 2.2 与现有项目的关系

| 项目 | 已有能力 | MoonRdiff 的定位 |
| --- | --- | --- |
| librsync / rdiff | 远程差量算法及摘要、补丁工具 | 作为格式与互操作参照，提供 MoonBit 实现 |
| MoonVCDIFF | VCDIFF 二进制补丁编码与解码 | 聚焦仅持有旧文件摘要时的差量计算，采用 librsync 格式路线 |
| rsync | 完整文件传输与同步工具 | 首版提供算法库，不声明兼容 rsync 网络协议 |

librsync 明确区分其算法库与 rsync 网络协议，并提供 signature、delta、patch 操作。[来源：librsync 项目说明](https://github.com/librsync/librsync)

MoonVCDIFF 已有源文件与目标文件之间的补丁编码能力，因此本项目的独立价值必须由“摘要参与计算”和 rdiff 互操作证明。[来源：MoonVCDIFF](https://mooncakes.io/docs/yangxixi00/moon_vcdiff)

截至本次公开检索，尚未发现直接对应的 MoonBit librsync 兼容实现。立项首阶段继续核查 GitHub、Mooncakes 和官方公开计划；未检索到不等于不存在，也不保证与未公开参赛项目不重复。

## 三、首版功能范围

### 3.1 必须交付

| 模块 | 功能 | 验收结果 |
| --- | --- | --- |
| 摘要生成 | 按块计算弱校验与强校验，读写明确支持的摘要格式 | 与固定版本 rdiff 相互使用摘要 |
| 差量计算 | 利用摘要识别新文件中的可复用块，生成复制和字面数据指令 | 计算端无需读取完整旧文件 |
| 补丁还原 | 从旧文件指定范围复制数据并写入新增内容 | 还原结果逐字节等于目标文件 |
| 分块接口 | 支持分批输入、输出容量限制、输入结束与截断判断 | 不同输入切分下结果一致，无丢失或重复消费 |
| 文件工具 | 提供 signature、delta、patch、verify 命令 | Windows、Linux 上完成单文件更新 |
| 集成示例 | 独立包消费者、两端通过文件交换摘要和补丁的演示 | 全新环境按 README 可复现 |
| 发布材料 | Mooncakes 包、README、接口文档、CI 与文字演示 | 新建消费者从正式包安装并运行 |

### 3.2 格式兼容策略

首选支持 `RS_RK_BLAKE2_SIG_MAGIC` 摘要方案，固定一组明确的块大小及强校验长度配置，再逐步扩展。其为 librsync 文档列出的推荐摘要类型；具体 BLAKE2 变体、初始化、截断与整数规则在首阶段锁定，不凭名称推断。[来源：librsync 公开接口](https://raw.githubusercontent.com/librsync/librsync/master/src/librsync.h)

首版补丁解码覆盖选定格式中的有效 literal、copy、end 指令及参数宽度，包括短 literal 指令。编码器可仅输出其中的规范子集。遇到未知格式、未支持的摘要类型或不合法参数时返回明确错误。

格式说明网页与实际指令表须同时核对，不能只按概述实现。[来源：格式说明](https://librsync.github.io/page_formats.html)、[指令表](https://raw.githubusercontent.com/librsync/librsync/master/src/prototab.c)

“兼容”限定为测试矩阵列明的格式、配置与参考版本；不要求两种编码器生成完全相同的补丁字节，要求能够交叉读取并正确还原。

### 3.3 首版边界

首版聚焦单文件，不纳入目录同步、权限迁移、网络服务、SSH、账号系统、图形界面、自动更新服务或完整备份产品。MD4 历史摘要格式不作为首版目标。

本项目中的 signature 指“分块摘要”，不是身份认证用的数字签名。CLI 验证可使用调用方提供的预期文件摘要，但摘要来源的可信性由应用负责。

## 四、技术设计

### 4.1 工作流程

```text
接收端：旧文件 → 分块摘要
                     ↓ 交换摘要
发送端：分块摘要 + 新文件 → 差量补丁
                              ↓ 交换补丁
接收端：旧文件 + 差量补丁 → 新文件 → 校验
```

核心库接收字节或调用方提供的读写接口。文件路径、进度展示和输出落盘由适配层负责，使算法可以在 Native、JavaScript 与 Wasm-GC 后端复用。首版原生 CLI 作为正式文件操作入口，浏览器示例放在后续扩展阶段。

### 4.2 资源与数据约束

- 摘要生成和新文件扫描支持分块输入；摘要索引内存随旧文件块数增长，须提供块数与内存预算限制。
- 补丁还原需要随机读取旧文件，不能把所有输入都描述为顺序流。
- 偏移和长度采用明确的宽整数表示；转为后端数组索引前检查范围，公布各后端实际支持上限。
- 以强校验确认候选块，避免只凭滚动校验认定匹配；限制候选搜索工作量，必要时输出字面数据保证正确性。
- 还原结果写入新文件，避免输入输出别名和覆盖原文件；错误返回保留原数据，未完成结果不得被标记为成功。
- 原始 rdiff 补丁不额外夹带自定义字段。预期旧文件、新文件摘要和验证信息可放在单独的清单中。

### 4.3 建议代码结构

```text
checksum/       滚动校验及强校验适配
signature/      摘要格式与生成
delta/          块匹配与补丁生成
patch/          补丁解析与还原
stream/         分块处理状态与公共接口
cmd/moonrdiff/  原生命令行工具
examples/       独立消费者与两端更新示例
tests/interop/  rdiff 互操作测试
benchmarks/     数据生成规则及基准
docs/           格式契约、安装、验证和发布记录
```

工具链在首阶段选定可核验的官方稳定版本并固定版本与来源；满足此前验收要求中的 moonc 不低于 0.10.16。参考 rdiff 同样固定版本和来源，CI 不依赖浮动 latest。

## 六、测试与验收标准

### 6.1 正确性与互操作

对每组旧文件 A、新文件 B，验证 `patch(A, delta(signature(A), B)) == B`。除内部往返外，必须覆盖四条跨实现路径：

1. MoonRdiff 摘要 → rdiff 差量 → MoonRdiff 还原。
2. MoonRdiff 摘要 → rdiff 差量 → rdiff 还原。
3. rdiff 摘要 → MoonRdiff 差量 → rdiff 还原。
4. rdiff 摘要 → MoonRdiff 差量 → MoonRdiff 还原。

测试必须对参考工具显式指定或记录格式配置，不能把不兼容默认值隐藏为工具失败。差量步骤在不含旧文件的独立目录执行，仅提供摘要和新文件。

样本覆盖空文件、完全相同、完全不同、追加、前部插入、中间删除、块移动、重复内容、二进制数据和尾块。错误测试覆盖截断、未知指令、非法长度、偏移溢出、越界复制、输出预算耗尽及输入结束状态；随机测试保留种子与最小失败样本。

### 6.2 平台与集成

- Native：Windows、Linux 执行库测试与 CLI 测试。
- JavaScript、Wasm-GC：执行核心库测试，验证整数、字节处理与分块行为一致。
- Linux：运行固定版本 rdiff 的完整双向互操作测试。
- CI 覆盖格式检查、静态检查、构建、测试、公开接口变化检查和打包验证。
- 发布后使用独立消费者从 Mooncakes 安装，验证文档命令与实际发布内容一致。

### 6.3 性能评测

首轮使用 1 MiB、16 MiB、128 MiB 的可重建数据，按相同、局部替换、插入删除、随机数据和压缩数据分组。记录摘要大小、补丁大小、摘要与补丁合计传输量、各阶段耗时、峰值内存及机器环境。

与相同配置的 rdiff 和直接传输完整文件比较。摘要成本计入首次交换；摘要复用另列场景。公开差量比完整文件更大的案例，不预先承诺提速或压缩比例。所有支持范围内的样本必须正确还原，性能结果用于指导后续优化。

## 七、许可证、协作与发布

原创实现计划使用 MIT 许可证。librsync 仓库声明 LGPL-2.1，实施前记录参考材料和依赖来源；若采用或移植其代码，按对应许可证重新安排文件许可和发布材料，不能直接改标 MIT。[来源：librsync 仓库许可说明](https://github.com/librsync/librsync)

优先复用社区中适用的校验、字节和文件接口库，避免无必要的重复实现。参考工具用于独立验证；第三方代码与测试数据的引入均记录来源、版本和许可证。

每个通过验收的里程碑推送一次，较长阶段按可独立验证的功能拆分提交。仓库持续维护 README、CHANGELOG、格式契约和验证记录。本地测试、云端测试与正式发布分别记录，不互相替代。

对外发布前给出具体版本、提交与附件清单；按届时已有授权执行。外部项目接入以可运行示例和接入文档为起点，联系维护者或提交外部 PR 时另行确认具体范围。
